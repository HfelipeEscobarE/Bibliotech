BIBLIOTECH - CAMBIOS SOBRE SAMPLE VAULT
=======================================

1) COPIAR
   Copia las carpetas backend/ y frontend/ de este zip sobre las de tu proyecto
   (acepta reemplazar archivos). Copia setup.sh a la raíz del proyecto.

2) BORRAR (ya no se usan)
   backend/controllers/sampleController.js
   backend/repositories/sampleRepo.js
   backend/routes/sampleRoutes.js
   frontend/html/producer-dashboard.html
   frontend/js/frontControllers/samplesFrontController.js
   frontend/js/tests/sampleTests.js

3) BASE DE DATOS (ahora se llama "bibliotech")
   - init.sql crea la base, el usuario y los Stored Procedures. Importalo como
     lo hacías antes (setup.sh, phpMyAdmin o consola).
   - Si ya tenías un .env con DB_USER / DB_PASS / DB_NAME = samplevault,
     cambialos a bibliotech (en backend/.env y en la copia de la raíz).
   - La base anterior "samplevault" no se borra sola; si ya no la necesitas,
     eliminala a mano.

4) ARRANCAR (desde la carpeta backend, porque uploads/ se resuelve desde ahí)
   cd backend
   npm install
   npm start

5) USUARIOS DE PRUEBA (contraseña 12345)
   admin        -> rol admin
   profesor     -> rol professor
   estudiante   -> rol student

6) QUÉ PROBAR
   - Sin iniciar sesión: ver el catálogo; "Leer" y "Descargar" piden login.
   - estudiante: lee y descarga PDF; no ve panel de subida.
   - profesor: sube un PDF (probá con tilde/ñ en el nombre), lo lee, lo descarga,
     lo borra; no puede borrar documentos de otro profesor.
   - admin: cambia el rol de un usuario, borra un documento ajeno, borra un
     usuario (sus PDF desaparecen también del disco).
   - Intentar subir un .txt o un .exe renombrado a .pdf.
   - Registrarse con una contraseña de 5 caracteres o con un usuario con espacios:
     el mensaje debe indicar qué campo está mal.
   - Registrarse con un usuario que ya existe (por ejemplo "admin").
   - Con NODE_ENV=testing: consola de pruebas de la API.

NOVEDADES (hito 2: filtros y manejo global de errores)
   - backend/utils/filter/    Módulo Filter: FilterHandler + reglas (ver su README.md)
   - backend/utils/i18n/      LanguageManager (Singleton) y diccionarios es.json / en.json
   - backend/utils/errors/    AppError y ValidationError
   - backend/middleware/filterMiddleware.js        Frena datos mal formados (400)
   - backend/middleware/globalErrorMiddleware.js   Responde TODOS los errores en JSON
     estándar { code, message, errors? } y no expone datos técnicos en producción.
   - Los controladores ya no responden errores a mano: usan next(error) / AppError.
   - Las rutas de registro, login, subida de documentos y cambio de rol llevan filtros.
   - Registro: usuario de 3 a 50 caracteres (letras, números, - _ .) y contraseña
     de 6 a 72 caracteres. El login no aplica esas reglas.
   - Idioma de los mensajes de error (opcional): agregar DEFAULT_LANG=en al .env.
     Sin esa línea se usa español.
   - NODE_ENV=production oculta el detalle técnico de los errores 500; con testing
     o development la respuesta incluye un campo "debug" útil para depurar.
   - Consola de tests (NODE_ENV=testing): nuevos casos de filtros, duplicados y errores.
